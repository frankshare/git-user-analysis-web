# Git 用户分析 · 高星 Skill 复用库

> 剖析顶级 GitHub 创作者的作品体系，把「一个爆款」拆成**可复用的方法**与**可上线的数据**。
> 本站与 star 排行榜的根本区别：**排行榜告诉你「谁红」，这里告诉你「什么是真的方法」。**

🌐 线上：https://frankshare.github.io/git-user-analysis-web/

## 核心发现：方法收敛簇

**23 位互不相识的创作者（中文 17 + 英文 6），在不同领域，独立收敛出同一组方法。**
样本 5 → 17 → 23 人三次复核，**六簇全部成立且覆盖数全部上升**，且在英文圈完全复现。

| 簇 | 名称 | 覆盖 | 一句话 |
| --- | --- | --- | --- |
| C1 | 门与闸门 | 11/23 | 把「做没做」变成机制问题 |
| C2 | 单一事实源与结构化分发 | **15/23** | 拒绝手工同步，让手改变成会报错的错误 |
| C3 | 渐进披露 | 7/23 | 入口轻，细节外置 |
| C4 | 可验证性 | 13/23 | 先证明，再宣称 |
| C5 | 边界声明 | 10/23 | 能力宣称要留出余地 |
| C6 | 内容即资产 | 11/23 | 把「品味」封成可枚举、可复用的集合 |

收敛判定：同一方法在 ≥3 位互不相识的创作者、不同领域独立出现，且各自给出**具体机制**（文件、脚本、测试、协议）而非同一句口号。

**五问拆解**：解决什么 / 核心机制 / 工程约束 / 能搬走什么 / **局限**。
没有「局限」一栏的拆解视为未完成——validator 会直接判失败。

## 数据完整性

- **单一事实源**：所有数字来自 `src/data/*.json`，页面里没有任何手写计数
- **fork 不参与聚合**：`repos[]` 保留 fork 并标 `fork: true`，`stats` 只算 `type=source`
- **口径写进页面**：每个用户页展示采集方式与已知误差；取不到的字段留空，不猜
- **validator 是唯一门禁**：复核聚合指标、ISO 时间、拆解卡五项齐备与 `stars`/`repo` 一致性

数据源在本地 Obsidian 库，通过 `scripts/sync-data.mjs` 同步；CI 环境用仓库内已提交的 `src/data` 作为兜底。

## 诚实边界

- 只看得到**公开**仓库；私有项目、真实用户量看不到
- star 是**流量指标**，不代表使用量、留存或收入
- HTML 抓取值有分钟级误差，跨快照只比趋势
- 「他为什么成功」只能给相关性解释，不能给因果证明
- 收敛簇由关键词匹配 + 人工核对得出，换一个归类者可能有不同结果
- 样本来源仍集中（21/23 来自两份策展清单），中英文比例失衡（17 vs 6）
